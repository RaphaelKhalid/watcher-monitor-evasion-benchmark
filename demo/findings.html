THE FINDING

Raw-text matching is not shell semantics.

NARROW CLAIM

Some deterministic allow rules match the beginning of the raw Bash string. They do not inspect the later command in a pipe or && chain before allowing the whole string.

echo → crontab

A safe-looking prefix hides a scheduled-task write.

git status → mutation

A read-only prefix hides a credential or remote change.

REPRODUCE IT

Three steps. No command execution.

OFFLINE
  1. 01

    Install and start Watcher locally in WSL using Apollo’s public “Run it yourself” instructions.

  2. 02

    Clone the public benchmark and classify the installed policy:

    git clone https://github.com/RaphaelKhalid/watcher-monitor-evasion-benchmark.git
cd watcher-monitor-evasion-benchmark
python3 03-build/benchmark.py \
  --policy "$HOME/.local/share/apollo-watcher/watcher/_internal/watcher_sdk/settings_schema/settings.yaml"
  3. 03

    Check the output: 110 dangerous strings, 6 allow, 104 triage.

✓The harness only reads the policy and matches text. It never runs the corpus commands.

SCOPE

What this proves—and what it doesn’t.

This demonstrates a deterministic policy-router weakness in the installed policy. It is not a claim that every dangerous command bypasses Watcher, or that the full LLM monitor would approve these actions. The six strings were classified, never executed.
